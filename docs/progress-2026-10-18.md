## English

### TL;DR
- **The service is live.** `https://bern-expertise.ch` runs over HTTPS, and **Apertus v1.5 70B** is connected through an OpenAI-compatible endpoint hosted in Switzerland (Keera gateway, CSCS).
- **Biggest gap for the jury:** `technical_report.md` §5 still says *"No Apertus numbers yet"*. Every metric we report comes from the rules baseline.
- **Proposal: from now until the submission, we focus on Apertus.** Run the extraction with Apertus, measure Apertus against the rules baseline, and write the results into the report and the demo.
- The paper/OpenAlex enrichment (PR #11, merged) has run two pilots on the server; the full run is planned after the cases fixes.

### Why Apertus must be the core of the submission
The jury scores six dimensions. Here is where each one stands and what Apertus adds:

| Criterion | Where we are | What Apertus adds |
|---|---|---|
| Purposeful use of AI | Apertus is wired in, but extraction still runs on rules. | Apertus does the **structured extraction with verbatim citations**, the plain-language request summary, the query expansion and the cited explanations, with abstention when nothing fits. |
| Technical rigour | The eval harness exists (`make eval`: recall@10, synonym twins, traceability, abstention). | **Apertus 8B vs 70B vs rules**, measured on the same golden set and the same pages. |
| Value, cost & scalability | We have no cost per request. | Tokens and latency per request and per page, plus the cost of a full re-extraction. |
| Sovereign deployability | One docker compose; the vLLM GPU profile or a Swiss endpoint. | Already demonstrated: an Apertus endpoint in Switzerland, no US API, open embeddings (`multilingual-e5-base`). |
| Implementation feasibility | Running live with HTTPS and a DB. | The same pipeline re-runs on new sources: unibe was added only through config. |
| Pitch | — | Show a live request answered with cited Apertus output, side by side with the rules-only output. |

### Proposed plan (Apertus first)
1. **Extract with Apertus 70B** over the 1,927 crawled pages, using `extract --extractor apertus`. The verifier keeps only claims backed by a verbatim snippet.
2. **Run the same extraction with Apertus 8B.** It is cheaper and faster; we compare its quality.
3. **Evaluate rules vs 8B vs 70B** with `make eval`, and record tokens, latency and rejected-claim rate.
4. **Fill in `technical_report.md` §3 and §5** with the real numbers, and remove *"No Apertus numbers yet"*.
5. **Re-index**: Postgres (PR #3 is merged) once activated, files otherwise. Redeploy, then record the 2-minute demo on the live site.
6. **Paper enrichment (PR #11, merged): two pilots done on the server.** Apertus 70B makes the author-match and topic decisions, always choosing from a whitelist given in the prompt; papers go to pgvector chunks and the AGE graph (`Paper`, `AUTHORED`, `CITES`, `ABOUT`, `SIMILAR_TO`). The pilots found three bugs, all fixed with tests: topic answer parsing + `papers topics --remap` (`2f5c8a8`), duplicate DOIs (`788a190`), NUL bytes in PDF text (`a922a10`); `--people {all,known,search}` selects who is processed (`5e6a5de`). Numbers: [`docs/papers-pilot-report.md`](papers-pilot-report.md). The full overnight run is planned after the cases fixes. The app still does not read Postgres (issue #7), so search does not use the papers yet.

### Decisions needed from the team
- **Activate the Postgres backend** (PR #3 is merged, `d77de8e`; blocked on issue #7), or tell us what is blocking it.
- **Apertus endpoint ownership.** Today it runs on a key lent by a team member. Do we keep it for the hackathon or request a dedicated one?
- **Who runs the Apertus extraction, and when.** It takes about 2k LLM calls on the shared server.

3. **Valutazione regole vs 8B vs 70B** con `make eval`, registrando token, latenza e tasso di claim scartati.
4. **Compilare `technical_report.md` §3 e §5** con i numeri reali, e togliere *"No Apertus numbers yet"*.
5. **Reindicizzazione**: su Postgres (la PR #3 è mergiata) una volta attivato, altrimenti su file. Nuovo deploy, poi registrazione della demo di 2 minuti sul sito live.
6. **Arricchimento con i paper (PR #11, mergiata): due pilot fatti sul server.** Apertus 70B prende le decisioni su autore e topic, scegliendo sempre da una whitelist passata nel prompt; i paper finiscono in chunk pgvector e nel grafo AGE (`Paper`, `AUTHORED`, `CITES`, `ABOUT`, `SIMILAR_TO`). Numeri: [`docs/papers-pilot-report.md`](papers-pilot-report.md). Il run completo notturno è previsto dopo i fix sulle richieste.
